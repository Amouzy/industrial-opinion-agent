# 产业舆情标签体系设计说明

## 设计目标

这套标签体系服务于产业研究员，而不是通用新闻读者。研究员关心的是“这条信息能否改变我的产业判断、报告结构、跟踪清单或风险提示”，因此标签必须能回答四类问题：

- 这属于哪个产业链环节？
- 这是什么类型的产业事件？
- 涉及哪些主体角色？
- 它释放的是机会、风险、政策、竞争、技术路线、商业化、区域还是资本市场信号？

系统当前聚焦两个目标行业：新能源汽车和人工智能。选择这两个行业是因为它们变化快、公开信息多、政策和企业动作密集，适合展示持续监控、分类、去重和事实提炼能力。

## 标签维度

### 1. 行业

- 新能源汽车
- 人工智能

行业标签用于决定后续细分 taxonomy。相关性筛选节点先判断候选是否进入这两个目标行业；分类节点只在已进入的行业内部做更细标签选择。

### 2. 行业细分

新能源汽车：

- 整车制造
- 动力电池
- 智能驾驶
- 充换电基础设施
- 汽车芯片
- 车载软件
- 上游材料
- 出口与海外市场

人工智能：

- 基础模型
- AI 芯片
- 算力基础设施
- AI 应用
- 智能体/Agent
- 数据与安全
- 机器人
- 企业服务

设计思路：细分标签按产业链和技术栈组织，而不是按新闻栏目组织。比如新能源汽车不只看整车品牌，还要覆盖电池、材料、智能驾驶、车载软件、补能和海外市场；人工智能不只看模型发布，还要覆盖芯片、算力、应用、安全、机器人和企业服务。

### 3. 事件类型

- 政策/监管
- 融资/投资
- 并购/重组
- 产品发布
- 技术突破
- 战略合作
- 产能/交付
- 价格/商业化
- 龙头企业动向
- 供应链变化
- 海外扩张
- 风险/负面舆情

设计思路：事件类型对应研究员日常报告中的“变化来源”。政策/监管和风险/负面舆情通常优先级高，因为它们可能改变行业约束；技术突破、供应链变化和龙头企业动向影响竞争格局；融资、并购和商业化体现资本和市场验证；产品发布本身不一定高优，只有关联核心主体、明确指标或商业化信号时才升权。

### 4. 主体角色

- 整车厂/模型厂商
- 核心零部件/芯片企业
- 电池/算力基础设施企业
- 政府/监管机构
- 高校/科研机构
- 投资机构
- 海外企业
- 下游客户/应用方

设计思路：主体角色帮助研究员判断事件的产业位置和影响路径。同样是“合作”，政府/监管机构参与可能意味着政策导向；下游客户参与可能意味着商业化验证；核心零部件/芯片企业参与可能意味着供应链变化。

### 5. 信号属性

- 机会信号
- 风险信号
- 政策信号
- 竞争格局变化
- 技术路线变化
- 商业化进展
- 区域产业变化
- 资本市场信号

设计思路：信号属性是面向研究结论的抽象层。事件类型回答“发生了什么”，信号属性回答“为什么值得跟踪”。例如“地方出台 AI 产业园政策”是政策/监管事件，同时也是政策信号和区域产业变化；“头部模型厂商发布企业 Agent 能力”可能同时是产品发布、商业化进展和竞争格局变化。

### 6. 重要性等级

- high：对产业格局、监管环境、核心主体、供应链、风险暴露或技术路线可能产生显著影响。
- medium：事实明确且有跟踪价值，但影响范围、持续性或产业传导仍需后续验证。
- low：影响局部、信息重复、事实较弱，或只有一般背景价值。

重要性不是情绪判断，也不是热度判断。系统会结合来源权威性、事件类型、核心主体、证据强度和潜在影响解释原因。

## 分类约束

LLM 分类节点必须遵守以下约束：

- 只能从固定枚举中选择标签，不能新增、改写或翻译标签。
- 只依据输入的标题、正文、摘要和来源元数据判断，不使用外部知识补全事实。
- 每个标签必须有原文或来源属性证据支撑。
- 不确定时选择更少标签和较低置信度。
- 不输出排序总分，排序由后端显式公式计算。
- 本地规则的候选分类结果不传给 LLM，避免影响模型独立判断。

系统会对 LLM 输出做结构化校验。标签越界、字段缺失或 payload 不完整时，结果不会入库，会回退到规则分类。

## 与排序的关系

标签体系为排序提供结构化输入，但不直接等同排序。排序使用以下信号：

- 重要性等级和分类置信度。
- 来源可靠性。
- 发布时间或抓取时间对应的时效性。
- 事件类型分值。
- 同事件可靠来源覆盖数。
- 关键主体等级。

这种设计把“模型判断”和“业务排序”拆开：模型负责理解文本和标签，后端负责可解释评分。

## 典型判断样例

### 政策监管

政府部门发布动力电池回收追溯政策：

- 行业：新能源汽车
- 行业细分：动力电池、上游材料
- 事件类型：政策/监管
- 主体角色：政府/监管机构、电池/算力基础设施企业
- 信号属性：政策信号、风险信号
- 重要性：high

原因：政策可能改变企业合规成本、回收体系和产业链责任边界。

### 企业产品

模型厂商发布企业级 Agent 能力：

- 行业：人工智能
- 行业细分：智能体/Agent、企业服务、AI 应用
- 事件类型：产品发布、价格/商业化或龙头企业动向
- 主体角色：整车厂/模型厂商、下游客户/应用方
- 信号属性：商业化进展、竞争格局变化
- 重要性：medium 或 high，取决于主体地位、客户证据和能力细节。

原因：如果只是普通版本更新，重要性较低；如果涉及核心厂商、企业客户和明确商业化能力，则应升权。

### 风险事件

智能驾驶事故、召回或监管处罚：

- 行业：新能源汽车
- 行业细分：智能驾驶、车载软件
- 事件类型：风险/负面舆情、政策/监管
- 主体角色：整车厂/模型厂商、政府/监管机构
- 信号属性：风险信号、政策信号、竞争格局变化
- 重要性：high

原因：风险事件可能触发监管、影响消费者认知和企业技术路线。

## 后续优化

- 增加人工标注和 Bad Case 回流，评估分类准确率、召回率和标签一致性。
- 将不同用户场景拆成权重模板，例如研究员晨报、政府监管、企业竞品监控。
- 在 Chroma 接入后，用相似事件召回辅助标签稳定性评估，但仍保留枚举校验和人工可解释规则。
